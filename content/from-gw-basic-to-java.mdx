My introduction to programming was GW-BASIC when I was 13. Java came later and became the first language I learned in depth.

Looking back, those were two different stages of learning. GW-BASIC was the beginning: getting familiar with the idea that instructions could become something a computer would do. Java was where I began thinking more deliberately about how a program should be organised.

## Learning to think beyond the screen

What interests me about programming is not just what appears on the screen. It is the logic underneath: how information moves, how decisions are made, and what should happen when something goes wrong.

That interest connects my early experience with Java to the web applications and business systems I work with today. The tools have changed, but I still care about the same questions. Does the software make sense? Can someone else maintain it? Does it make a real task easier?

## Why Java still interests me

Java remains part of how I think about backend development. I am interested in the structure behind an application, not just its individual features.

Working with Java and Spring Boot is another way to explore that structure: separating the interface from business rules, making responsibilities explicit, and thinking carefully about how an application handles data and errors.

## Thinking about a banking API

One concept I want to explore is a banking-style operations API built with Java and Spring Boot.

The proposed scope is deliberately focused: account records, transaction history, and transfers using synthetic data. I would pay particular attention to transactional updates, repeated requests, and an audit trail that explains what happened.

This is an independent design concept, not a production banking system or client implementation.

## The part that has stayed the same

I started with GW-BASIC at 13, went deeper with Java, and eventually found my way into web development and business applications.

I do not see those as disconnected chapters. They are different ways of pursuing the same interest: understanding a problem well enough to build something useful.
