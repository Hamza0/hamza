If Stripe shows a successful payment while WooCommerce says Pending payment, check the matching records first. Do not ask the customer to pay again yet.

## Match the order and payment

Compare the order number, transaction reference, amount, currency and time. Check that you are looking at the correct account and live or test environment.

WooCommerce normally uses Pending payment for an order awaiting payment. Processing generally means payment was received and the order awaits fulfilment. Its [order-status guide](https://woocommerce.com/document/managing-orders/order-statuses/) explains the exceptions.

Changing the status just to make the screens agree can hide the original problem. Establish what happened to the existing payment first.

## Check the update sent to the store

Stripe sends payment updates through webhooks: messages that tell the store an event occurred. WooCommerce's [Stripe webhook guide](https://woocommerce.com/document/stripe/setup-and-configuration/stripe-webhooks/) explains how this connection is configured and checked.

Follow the instructions for the installed extension version. Supported versions configure webhooks when connecting to Stripe, so creating another connection without checking the existing setup can add confusion.

A received message and an updated order are separate checks. Stripe's [webhook guidance](https://docs.stripe.com/webhooks) recommends acknowledging messages before lengthy processing, so a successful delivery response does not prove the order changed correctly.

## Put the records in order

Collect the order notes, exact payment state and relevant event delivery time and response. Include the WooCommerce and payment-extension versions and any recent changes.

Build a short timeline. Was an update sent? Did the store receive it? Does an order note show an error? Is one order affected or several?

Keep account secrets and unnecessary customer information out of shared screenshots. A similar problem reported online may have a different cause.

## Confirm the outcome before acting

Have the payment and order checked together before requesting another payment, issuing a refund or changing fulfilment status. The reviewer should explain what is confirmed and what the proposed action will do.

Check any integration change in a suitable test environment. Repeated updates should not trigger duplicate actions. The same distinction appears in [how systems handle uncertain requests](/blog/apis-are-where-systems-start-talking).
